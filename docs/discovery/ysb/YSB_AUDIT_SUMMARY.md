# 药师帮区域商家经营审计摘要

## 1. 核心结论

1. 当前主看板应使用绩效与商家销售额汇总目录，不使用日报作为全区域订单事实源。
2. 最适合近期 Dashboard A 的主数据源是“销售额统计（按月）”长表：最完整版本覆盖 91 家商家、2026-03 至 2026-06。
3. “商业每月GMV”宽表提供最长历史候选：2023-01 至 2026-05 的 41 个 `aYYYYMM` 月列，最多 112 个供应商 ID，但部分月份只有约 99 家有值。
4. 商业每月GMV的最新版本是筛选子集，不能直接代表全区域覆盖。
5. 绩效表存在整体/人员级目标，也存在商家级实际，但尚未证明 target 与 actual 能以同一粒度关联。
6. V1 可以使用 `merchant_natural_key` 做 staging，不必等待正式 `merchant_id`。
7. Dashboard A 当前最安全的是月度销售/GMV候选、订单数、售后率、排名和运营/商务归属。
8. `药师帮日报.xlsx` 保留为 Dashboard B 的按需单商家诊断源。
9. 当前不建设全区域订单事实仓库，不开始 M4 UI。

## 2. 区域主数据候选

详见 `YSB_REGIONAL_DASHBOARD_SOURCE_MAP.md`。推荐主源为销售额统计（按月）长表，历史辅助源为商业每月GMV宽表，售后和新开商业表作为异常辅助源。

## 3. 当前可做指标

月销售额/现金额候选、月 GMV 候选、订单数、售后订单数/率、环比、排名、运营/商务归属、商家和月份覆盖度。

## 4. 当前不应自动发布

商家级目标达成率、新开商家 KPI、有效品次、统一商家排名的跨版本全历史结果、区域贡献度总额和正式异常分数。

## 5. 真正阻塞项

目标与实际的同粒度关联、宽表版本覆盖完整性、商家自然键历史稳定性、内部区域定义，以及销售额/GMV业务口径确认。
