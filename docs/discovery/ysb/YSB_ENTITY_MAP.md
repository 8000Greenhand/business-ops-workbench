# 药师帮第二轮实体定版审计

## Merchant

当前：`BLOCKED`。

日报没有可确认的商家 ID/商业 ID 主键。订单原始数据的 `供应商` 字段只有 2 个非空值，表现为供应商/来源分类，不能直接等同于平台商家。绩效文件虽有商家/商业/运营候选字段，但尚未建立跨版本稳定映射。

商家名称不能作为正式唯一键；名称变更、后缀和同名问题尚未完成映射。

## Customer / Pharmacy

当前：`PARTIAL`。

订单原始数据有 `药店编码`、`药店全称`、药店类型、省、市、区/县。药店编码与药店全称各有约 6,790 个非空唯一值，具备下游采购客户候选键，但仍需确认有效订单去重与客户主数据规则。

明确不把 Customer 与 Merchant 合并。

## Product

当前：`LIKELY`。

订单原始数据同时有 `商品ID`、`商品编码`、产品名称、厂家、规格；商品 ID 约 508 个非空唯一值，商品编码约 500 个，且商品编码出现前导零。后续候选优先级为：商品/药品 ID，其次商品/药品编码，再其次品种编码；需要跨活动、订单、平台准入价表验证。

## Activity

当前：`PARTIAL`。

活动原始数据有活动 ID、关联活动 ID、活动类型、状态、商品和价格；订单侧也有活动 ID/类型，存在关联候选，但尚未确认完整外键及有效期规则。

## Region / Operator

订单侧的省、市、区/县可以支持地理维度候选；绩效文件包含区域/运营/商务候选字段。当前不能把地理行政区直接当作内部区域组织，也不能确认人员历史归属。

## 关系结论

- Region → Merchant：`BLOCKED`，缺稳定商家键。
- Merchant → Product：`BLOCKED`，缺稳定商家键和跨表商品验证。
- Product ↔ Activity：`PARTIAL`，有商品/活动 ID 候选。
- Order → Customer/Pharmacy：`LIKELY`，订单明细有药店编码。
- Operator/Region → KPI：`PARTIAL`，目标与实际尚未同粒度关联。
